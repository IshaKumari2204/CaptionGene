# CaptionGene Annotation Guidelines (v0.2, Week 2)

These rules are for anyone who generates, verifies, or edits captions and instructions.
The machine-readable definitions are in `configs/taxonomy.yaml` and `schema/annotation_schema.json`.

## 1. What gets annotated

Each **image** has:
- a **scene** block: environment, clutter level, object count, and whether the items are discarded
- a list of **objects**. Each object has a box and polygon from the source dataset plus structured fields
- image-level **captions**: VLM candidates and human edits, each with a review status

Each **object** has five structured fields:

| Field | Values | Who fills it |
|---|---|---|
| `category` | 15 classes (bottle_jar, can, carton_box, cup, bag_wrapper, container_packaging, cap_lid, paper, straw_utensil, cigarette, food_waste, glass_fragment, hazardous, other_litter, unspecified) | auto from source label; humans fix `unspecified` |
| `material` | plastic, metal, glass, paper_cardboard, organic, composite, textile_rubber, e_waste, unknown | auto from source label; humans fix `unknown` |
| `condition` | multi-label: intact, crushed, dented, crumpled, torn, broken, open, soiled, wet, burnt, faded, partially_occluded, heavily_occluded | VLM proposes (Week 2), human verifies (Week 3) |
| `location` | 3×3 grid region + size (small/medium/large) | auto from the box |
| `sorting_action` | recycle_plastic / metal / paper / glass, compost, landfill, hazardous_dropoff, needs_review | auto default; condition overrides apply (e.g. a soiled pizza box goes to landfill) |

## 2. Caption style

**Object caption** template: `[condition] [colour] [material] [category noun] [location/context]`

- ✅ "crushed clear plastic bottle lying on gravel at the bottom-left"
- ✅ "torn brown cardboard box partly covered by a plastic bag"
- ❌ "a bottle" (too vague: no material and no condition)
- ❌ "a Coca-Cola bottle someone threw away yesterday" (brand names and made-up backstory are not allowed)

**Image caption**: 1–2 sentences. Name the main waste objects and their materials, then the clutter level and the background.
- ✅ "Three pieces of litter on a sidewalk: a crushed aluminium drink can, a clear plastic bottle, and a cigarette butt."

## 3. Hard rules (verification checklist)

1. **Only describe what is visible.** Remove any object, colour, or brand the image does not clearly show (hallucination).
2. **Material must match the label.** If the caption says "glass" but the object's `material` is plastic, either fix the caption or, if the source label is wrong, fix the label and add a note.
3. **Count must match.** "two cans" must agree with the number of `can` objects.
4. **Uncertain means generic.** If you cannot tell plastic from glass, write "bottle" and leave `material: unknown`. Never guess.
5. **Occluded objects:** add `partially_occluded` (under 50% hidden) or `heavily_occluded` (50% or more hidden).
6. **COCO images:** the objects may still be in use. Set `is_discarded` to yes or no, and do not call an in-use cup "waste".
7. **Tiny objects** (`flags: tiny`) do not need an object caption, but they still count toward the scene count.

## 4. Review statuses

| Status | Meaning |
|---|---|
| `pending` | generated by a model, nobody has checked it yet |
| `approved` | correct as generated |
| `edited` | a human corrected it (the original model output is kept in history) |
| `rejected` | unusable (hallucinated, wrong object, or empty) |

A **review_score** from 1 to 5 is recorded per caption: 5 = complete and correct; 3 = correct but missing material or condition; 1 = wrong or hallucinated.

## 5. Reviewing VLM caption candidates (added in Week 2)

Every image has image-level candidates from several models, and every non-tiny object (up to 8 per image,
largest first) has object-level candidates generated from a padded crop of its box. In the curation app
(`streamlit run app/streamlit_app.py`):

1. Read the candidates **side by side** (BLIP-family vs instruction-tuned VLM). The `template` caption is
   built only from the dataset labels; use it as a checklist of what *should* be mentioned, not as truth.
2. Check the **auto-check badges** first. They are keyword rules, so they can be wrong both ways:
   - ⚠️ *unsupported* - the caption names an object category that is not in the labels -> likely
     hallucination. Exception: ZeroWaste frames have unlabeled objects, so look at the image before
     marking it as a hallucination.
   - ⚠️ *material conflict* - the caption names a material, but not the labelled one.
   - ⚠️ *brand/text* - the caption quotes label text or a brand (not allowed, rule 2 above). Remove it.
3. **Approve** if the caption follows the rules above. **Edit** if it needs small fixes (the model text is
   kept as `original_text`). **Reject** if it is wrong or hallucinated (score 1). Write your own caption if
   every candidate is rejected.
4. Give a **review score** (section 4) and tick any **hallucinated objects**.
5. In the Objects tab, accept the **VLM-proposed conditions** only if you can see them, and fix the
   category / material if the source label is wrong.

Every action is appended to `data/reviews/reviews.jsonl` with the reviewer name and a timestamp, so
reviews can be audited and inter-annotator agreement can be measured later.

## 6. Sorting instruction style (Week 3)

Template: `"Pick up the <condition> <material> <category> at the <region> and place it in the <bin>."`
Each instruction must reference exactly one `object_id` (and therefore one box or mask).
